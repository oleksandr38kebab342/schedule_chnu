# Product Vision та User Story Map

**Спринт 1** · БА + PM + UI/UX + тімліди.

## Product Vision
**Для** диспетчерів, викладачів і студентів університету, **яким** потрібен надійний, актуальний розклад,
**Інформаційна система управління та відображення навчального розкладу** — це вебзастосунок,
**що** формує, перевіряє на конфлікти і показує розклад з урахуванням підгруп, потоків, парних/непарних тижнів та винятків.
**На відміну від** розрізнених Excel/Word-файлів, **наш продукт** виявляє конфлікти до збереження, веде журнал змін, працює зручно на телефоні і вивантажує розклад в Excel «як для друку».

## User Story Map
**Backbone (активності зліва направо):**
Налаштувати довідники → Задати календар → Скласти розклад → Перевірити конфлікти → Переглянути розклад → Експорт / імпорт → Адмініструвати

| Активність | Історії (пріоритет) | Реліз |
|---|---|---|
| Налаштувати довідники | Адмін створює факультети, кафедри, викладачів, групи, підгрупи, потоки, дисципліни, корпуси, аудиторії, час пар (Must) | MVP-1 |
| Задати календар | Адмін створює рік і семестри; система генерує навчальні тижні з парністю; додає канікули/свята/робочі суботи (Must) | MVP-2 |
| Скласти розклад | Диспетчер створює/редагує/видаляє заняття з кількома групами, викладачами, аудиторіями; перенесення й скасування (Must) | MVP-3 |
| Перевірити конфлікти | Диспетчер бачить конфлікт з поясненням; з правом зберігає попри конфлікт із причиною; усе пишеться в audit (Must) | MVP-4 |
| Переглянути розклад | Студент/викладач відкривають розклад групи, викладача, аудиторії, кафедри; екран «Сьогодні» на телефоні (Must/Should) | MVP-3, далі UI |
| Переглянути швидко | Розклади віддаються з Redis-кешу, кеш інвалідується при змінах (Should) | MVP-5 |
| Експорт / імпорт | Адмін вибирає групи й отримує .xlsx; імпорт з попереднім переглядом (Must/Should) | MVP-6, імпорт далі |
| Адмініструвати | Керування користувачами, ролями, правами, перегляд audit (Must) | MVP-1 / MVP-4 |

**Пріоритети:** Must — конфлікти, розклад, календар, експорт; Should — Redis, мобільний екран, імпорт; Could — масові операції, drag&drop.
**Майбутнє (не MVP):** Telegram-бот, push, автогенерація розкладу, SSO/LDAP, LMS.
