# Публічний API перегляду розкладу

**Спринт 4** · backend. Джерела: розділи 29–33, 94 ТЗ; персони «Софія» і «Олег».

## Рішення: розклад видно без входу
Опублікований розклад — відкрита інформація університету. Вимагати обліковий
запис від студента, щоб подивитися свою пару з телефона, суперечить сценарію
«за 5 секунд побачити Сьогодні». Тому читання винесено в окремий роутер
`/api/v1/public`, де **немає жодного методу запису** (це перевіряє тест
`test_public_router_is_read_only`).

Якщо університет вирішить закрити розклад — прапорець
`PUBLIC_SCHEDULE_ENABLED=false` вимикає весь роутер одним рядком конфігурації.
Усе, що змінює дані, лишилося в захищених роутерах із перевіркою прав на
backend (розділ 4 ТЗ).

## Ендпоінти
| Метод | Шлях | Призначення |
|---|---|---|
| GET | `/public/groups?search=&faculty_id=` | групи з кафедрою й факультетом, природне сортування |
| GET | `/public/groups/{id}/subgroups` | підгрупи для перемикача |
| GET | `/public/teachers?search=` | викладачі з кафедрами |
| GET | `/public/rooms?search=` | аудиторії; пошук нечутливий до «А.203 / А203 / А-203» |
| GET | `/public/lesson-types`, `/public/times` | легенда типів і сітка пар |
| GET | `/public/calendar?date=` | семестр, номер тижня, парність, чи навчальний день |
| GET | `/public/schedule/group/{id}/day?date=&subgroup_id=` | день групи |
| GET | `/public/schedule/group/{id}/week?date=&subgroup_id=` | тиждень групи |
| GET | `/public/schedule/teacher/{id}/{day\|week}` | розклад викладача |
| GET | `/public/schedule/room/{id}/{day\|week}` | зайнятість аудиторії |

`date` необовʼязкова: без неї повертається сьогодні.

## Формат відповіді
`DayView` містить контекст (`week_number`, `parity`, `is_working`,
`closed_reason`) і список `LessonView` — уже з назвами, а не ідентифікаторами:
дисципліна, тип, викладачі (з ознакою `is_substitute`), аудиторії з корпусом і
поверхом, групи/підгрупи/потоки, статус зміни та її причина.

`WeekView` повертає Пн–Пт завжди, а Сб і Нд — лише якщо там є заняття
(робоча субота, перенесення). Те саме правило діє в Excel-експорті, тому
паперовий і екранний розклад не розходяться.

## CORS
Фронтенд живе на іншому порту (Vite — 5173, Nginx — 8080), тому в
`app/main.py` увімкнено CORS зі списком джерел із `CORS_ORIGINS`. У
продакшн-збірці Nginx проксює `/api` на бекенд, і CORS взагалі не потрібен.

## Що свідомо не робили
- **Кешування публічних відповідей у Redis.** Кеш розкладу груп уже є на рівні
  `/schedule/group/{id}`; денормалізований вигляд залежить ще й від дати, тому
  його ключі й інвалідацію краще робити разом із навантажувальним тестом.
- **Пагінацію довідників.** Групи й аудиторії університету — це сотні рядків,
  не тисячі; фільтр `search` уже є.
